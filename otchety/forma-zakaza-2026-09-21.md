# Отчёт 21.09.2026: форма заказа на сайте — задачи 50, 51, 52

**Вывод одной строкой.** Письмо о заказе до почты **не доходит и не отправляется вовсе**: `mail()` на Hostland возвращает `false` (в PHP прописано `sendmail_path = /usr/bin/false`), поэтому «за сколько секунд» — не применимо; сам заказ принимается за **1,1–2,6 с** и сохраняется только в `data/orders.csv` [Certain].

Остальное работает: форма принимает заказ, пишет строку, показывает кнопку оплаты, ботов отсекает, файл с заказами снаружи закрыт [Certain]. Не работает одно — уведомление. Пока оно не починено, о заказе с сайта Игорь узнаёт, только если сам откроет `orders.csv` в панели хостинга.

## 2. Почему нет письма

Причина не в коде и не в адресе: на тарифе Hostland функция `mail()` отключена на уровне PHP — `sendmail_path = /usr/bin/false`. Любой вызов возвращает `false`, письмо не передаётся никакому почтовому серверу [Certain]. `order.php` это видит и честно пишет в седьмой столбец `НЕ ОТПРАВЛЕНО` — по всем 5 строкам.

**Следствие важнее самой находки.** `lead.php` шлёт письма тем же `mail()` — значит, письма с формы чек-листа на главной **не приходили никогда** [Certain по механизму; сам ящик info@el-group.com.ru Code не видит]. В `data/leads.csv` лежит **50 строк с 30.08 по 20.09.2026**, за 21 день; из них 13 — за 18–20.09, то есть после запуска кампании. Сколько из них живые люди, а сколько боты и тесты — UNKNOWN, файл Code только посчитал, не менял. `lead.php` и `leads.csv` не тронуты.

Что ещё проверено про обходные пути:

- исходящий HTTPS с хостинга работает (mail.ru — 200, yookassa.ru — 200);
- `api.telegram.org` с хостинга **недоступен** (таймаут соединения) — блок Telegram в `order.php` не заработает, даже если положить `data/tg.conf`;
- у домена `argument-law.ru` **нет SPF-записи**; почта `el-group.com.ru` ведётся на Яндексе. Даже когда отправка заработает, письма «от site@argument-law.ru» без SPF рискуют уйти в спам.

## 3. Что сделано

**Задача 50 — `order.php`.** Лежит в `elg-pzz/site-server/order.php`, сделан по образцу `lead.php`: тот же порядок проверок, тот же honeypot, тот же `mail()`. Отличия намеренные: тема письма кириллицей кодируется по RFC 2047; `orders.csv` создаётся с BOM и строкой заголовков; результат отправки письма пишется седьмым столбцом; длина полей считается в символах, а не в байтах.

**Задача 51.1 — выкладка.** `order.php` и две страницы на Hostland, способом от 17.09. Размеры: `proverka-izyatie-krt.html` 69 468, `gradprofil.html` 72 656, `order.php` 5 709 байт.

**Расхождение сервера с репозиторием — найдено при сверке и устранено.** На сервере лежала версия `order.php` с укороченными комментариями, и в ней метка продукта была записана как «В2»/«В1а» вместо «Г2»/«Г1а» — одна буква, остальной код совпадал построчно. Письма не уходили, поэтому метка никуда не попала. Файл перезалит из репозитория, после чего SHA-256 серверного файла совпал с локальным (`90851ce2…`), а все ветки проверены заново — результаты в таблице выше уже после перезаливки.

## 4. Одно замечание к вёрстке формы

Цель `order_form_*` в присланной вёрстке вызывается в `.finally()` — то есть и при успехе, и при ошибке отправки. Человек, у которого заказ **не** ушёл (блок «не получилось»), всё равно посчитается заявкой. Случай редкий, но цель по названию обещает другое. Правка — перенести вызов из `.finally()` в ветку успеха, одна строка на каждой странице. Code вёрстку Игоря сам не менял.

## 5. Решения за Игорем

1. **Уведомление о заказе — главное.** Варианты по убыванию надёжности:
   - отправка через SMTP ящика на Яндексе (пароль приложения создаёт и кладёт в `data/` сам Игорь; Code паролей не вводит и не хранит) — письмо уйдёт с настоящего ящика, вопрос SPF отпадает;
   - запрос в поддержку Hostland: включается ли `mail()` на тарифе. Если да — заработают сразу и `order.php`, и `lead.php`, но SPF для `argument-law.ru` всё равно понадобится;
   - до решения — раз в день открывать `data/orders.csv` в панели.
2. **Просмотреть `leads.csv`** — 50 строк, о которых писем не было. 13 из них за последние три дня.
3. **`.finally()` в форме** — править или оставить как известную неточность.
4. **Пять тестовых строк в `orders.csv`** — контакты `test1–3@example.com`, `+7 985 000-00-00` и один адрес Игоря. Code на сервере ничего не удаляет; чистить или оставить — решение Игоря.
